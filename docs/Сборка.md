# Сборка и установка

В проекте два разных Android-приложения. Автономный APK «Буква за буквой» содержит игру внутри пакета и подходит для установки без сервера. Официальная песочница организаторов открывает игру по URL и обязательна для проверки на защите. Автономный контейнер её не заменяет.

## Инструменты

- Python 3.10 или новее, Git, JDK 21.
- Android SDK Platform 36 и Build Tools 36.0.0 для автономного контейнера.
- Platform Tools для установки через `adb`.
- Для официальной песочницы дополнительно SDK Platform 36.1; её Gradle 9.4.1 и зависимости загружаются штатным wrapper.
- Для эмулятора на Mac с Apple Silicon нужны Android Emulator и системный образ `arm64-v8a`. Это необязательный инструмент проверки, не часть игры.

SDK размещается в `.work/android-sdk`, ключ подписи в `.work/android-signing`, временные сборки в `.work/android-build`, готовые APK в `artifacts/`. Эти каталоги исключены из Git. Глобальные настройки Java и Android SDK не меняются.

Command-line Tools скачиваются только с официального сайта Android. Перед использованием Android SDK владелец должен принять показанный установщиком лицензионный договор. Скрипты проекта не принимают договор автоматически. Установка пакетов после принятия выполняется через SDK Manager:

```sh
export JAVA_HOME=/путь/к/jdk-21
.work/android-sdk/cmdline-tools/latest/bin/sdkmanager \
  --sdk_root=.work/android-sdk \
  'platforms;android-36' 'build-tools;36.0.0' 'platform-tools'
```

В Command-line Tools 23.0 установщик `sdkmanager` переключён на native Android CLI. Загруженный пакет `mac_x86_64` содержит исполняемый файл x86, который без Rosetta на Apple Silicon не запускается. Java-реализация в том же официальном комплекте доступна такой командой:

```sh
"$JAVA_HOME/bin/java" \
  -cp '.work/android-sdk/cmdline-tools/latest/lib/*' \
  com.android.sdklib.tool.sdkmanager.SdkManagerCli \
  --sdk_root=.work/android-sdk \
  'platforms;android-36' 'build-tools;36.0.0' 'platform-tools'
```

Контрольная сумма использованного архива `commandlinetools-mac_x86_64-16111833_latest.zip`: SHA-1 `112cf9618794a997ff273537d55bee02c22abffe`. Контрольная сумма проверяется до распаковки. Версия пакета — 23.0; для воспроизведения следует использовать тот же архив, а не полагаться на изменяющееся имя `latest`.

## Автономный APK

Сначала завершите изменения файлов. Скрипт проверяет хеши игры и оболочки до и после сборки и отклоняет результат, если они изменились в процессе.

```sh
python3 scripts/build_android.py --java-home "$JAVA_HOME" --check-tools
python3 -B /Users/yuzuru/.agents/skills/workstation-dev/scripts/dev.py run \
  --cwd /Users/yuzuru/Projects/bukva-za-bukvoy --java 21 --resource heavy -- \
  python3 scripts/build_android.py --java-home "$JAVA_HOME"
```

Последняя команда использует локальный helper владельца для блокировки тяжёлых проверок и привязки результата к исходникам. На другом компьютере достаточно запустить `python3 scripts/build_android.py --java-home "$JAVA_HOME"`; SDK можно передать параметром `--sdk /путь/к/sdk`.

Сборка использует `aapt2`, `javac`, `d8`, `zipalign`, `apksigner` из официального SDK. Gradle и сторонние библиотеки автономному контейнеру не нужны. Минимальная система — Android 8.0, API 26; целевая — API 36. Идентификатор приложения: `ru.bukvazabukvoy.game`.

`minSdk 26` означает возможность установки контейнера, но не подтверждает работу веб-игры на заводском WebView Android 8. Для игры нужен актуальный Android System WebView с ES modules, `flex-gap`, `replaceChildren` и `aspect-ratio`. Использованный эмулятор Android 16/API 36 содержит WebView 133.0.6943.137. Физический Android 8 и его заводской WebView остаются непроверенными; одной компиляции для такого вывода недостаточно.

Результат: `artifacts/bukva-za-bukvoy-android.apk`. Рядом лежит JSON с SHA-256 APK, хешем файлов игры, ревизией Git и параметрами инструментов. Повторяется процедура сборки; побайтовая идентичность APK разных запусков не обещается.

При первой сборке создаётся локальный ключ разработки. Ключ и его пароль не попадают в Git или аргументы команд. Это ключ для установки и проверки, не опубликованный ключ релиза. Сохраните каталог `.work/android-signing`, если нужно обновлять уже установленное приложение без удаления; другой ключ потребует переустановки.

Установка с компьютера на подключённый телефон с разрешённой USB-отладкой:

```sh
.work/android-sdk/platform-tools/adb devices
.work/android-sdk/platform-tools/adb install -r artifacts/bukva-za-bukvoy-android.apk
```

Можно перенести APK на телефон и открыть его, разрешив установку из выбранного файлового приложения. Google Play не требуется. Это установочный APK, а не Android App Bundle.

## Изоляция автономного контейнера

Игра открывается с внутреннего адреса `https://game.bukva.invalid/index.html`. Запросы этого адреса перехватываются через `shouldInterceptRequest` и получают ресурсы APK; реального сервера и DNS-запросов нет. Разрешение `INTERNET` отсутствует, сетевые загрузки, `file://`, `content://` в WebView, внешние переходы и новые окна заблокированы. Для предпросмотра результата разрешён встроенный PNG data URL, который создаёт сама игра. Контейнер добавляет свой мост в ответ HTML, не меняя файлы `game/`.

Хранилище DOM отключено, кэш очищается при открытии и закрытии. Прогресс существует только в памяти до закрытия процесса/экрана; при обычном повороте WebView сохраняется. Масштабирование системного шрифта и чтение экранным диктором зависят от семантики самой веб-игры.

Системный жест или кнопка «Назад» передаётся игре через локальное событие `bukva-back`: на Android 13+ используется `OnBackInvokedDispatcher`, на Android 8–12 — `onBackPressed`. Поэтому подтверждение выхода из раунда и закрытие подсказки совпадают с поведением экранной кнопки игры.

Поддерживаются только `CLOSE_EVENT`, `FINISH_EVENT`, `COMPLETED_EVENT`, `VIBRATION_EVENT`, `SHARING_EVENT`. У шаринга плоские поля `text` и `image`, где `image` — PNG data URL. Если картинка отсутствует, можно отправить один текст длиной до 500 символов. PNG ограничен 2 МБ, стороной 4096 пикселей и площадью 4 194 304 пикселей. Получатель получает временное разрешение только на чтение конкретной картинки через закрытый `ContentProvider`; произвольные файлы передать нельзя. Картинка остаётся во внутреннем кэше для системной отправки, файлы старше суток удаляются при следующем открытии. Данные ребёнка в неё не добавляются.

## Неизменённая официальная песочница

Источник: [vveidi/sber-hse-hackathon-2026-android](https://github.com/vveidi/sber-hse-hackathon-2026-android). Закреплённая ревизия: `1ba091d72e9e0917af70d88319de51522a54f207`.

После принятия SDK-лицензии установите `platforms;android-36.1` тем же SDK Manager. Затем:

```sh
python3 -B /Users/yuzuru/.agents/skills/workstation-dev/scripts/dev.py run \
  --cwd /Users/yuzuru/Projects/bukva-za-bukvoy --java 21 --resource heavy -- \
  python3 scripts/build_sandbox.py --java-home "$JAVA_HOME"
```

Скрипт клонирует исходники в `.work/official-android`, проверяет точную ревизию и отсутствие изменений, вызывает официальный Gradle wrapper и копирует результат в `artifacts/official-sandbox-android.apk`. Игра внутрь песочницы не встраивается, исходники организаторов не правятся. Зависимости и Gradle кэшируются только в `.work/official-gradle`, служебные файлы Android и ключ отладочной песочницы — в `.work/official-android-user`.

Для локальной проверки игры запустите её сервер по инструкции README. На стартовом экране официальной песочницы в Android Emulator введите `http://10.0.2.2:8877`. Для реального телефона компьютер и телефон должны быть в одной сети; укажите локальный IP компьютера и порт. Если сервер слушает только `127.0.0.1`, для телефона его нужно явно привязать к локальному интерфейсу. Проверка на эмуляторе не заменяет проверку на реальном телефоне.

## Эмулятор на Mac с Apple Silicon

В рабочем окружении установлен Android Emulator 37.2.12 и AOSP-образ `system-images;android-36;default;arm64-v8a`, ревизия 2. Создан отдельный профиль `BukvaPixel`: Pixel 5, экран 1080 × 2340, плотность 440 dpi, около 393 точек по ширине. Образ без Google Play и Google-аккаунта.

Создание такого профиля на другом Mac после установки пакетов `emulator` и `system-images;android-36;default;arm64-v8a`:

```sh
mkdir -p .work/avd .work/android-user
ANDROID_AVD_HOME="$PWD/.work/avd" ANDROID_USER_HOME="$PWD/.work/android-user" \
  .work/android-sdk/cmdline-tools/latest/bin/avdmanager create avd \
  --name BukvaPixel --package 'system-images;android-36;default;arm64-v8a' \
  --device pixel_5 --path "$PWD/.work/avd/BukvaPixel.avd"
```

Запуск окна эмулятора без сохранения снимка и сбора метрик:

```sh
ANDROID_HOME="$PWD/.work/android-sdk" ANDROID_AVD_HOME="$PWD/.work/avd" \
  ANDROID_USER_HOME="$PWD/.work/android-user" \
  .work/android-sdk/emulator/emulator -avd BukvaPixel -gpu host \
  -no-snapshot -no-boot-anim -no-audio -no-metrics
```

Каталоги профиля и системного образа находятся внутри игнорируемой `.work`. В исходники игры и репозиторий они не входят. Установка APK в эмулятор использует ту же команду `adb install -r`, что и телефон. Эмулятор позволяет проверить WebView, поворот, системную кнопку «Назад» и меню отправки; проверку на физическом устройстве нужно проводить отдельно.

## Основания реализации

- [Официальные инструменты SDK](https://developer.android.com/tools).
- [Локальный веб-контент и безопасный HTTPS origin](https://developer.android.com/develop/ui/views/layout/webapps/load-local-content).
- [ContentProvider и доступ к файлам через URI](https://developer.android.com/guide/topics/providers/content-provider-creating).
- [SDK Manager и установка пакетов](https://developer.android.com/tools/sdkmanager).

Общая рекомендация Android — `WebViewAssetLoader` из AndroidX. Здесь ту же схему HTTPS origin и перехвата реализует небольшая собственная оболочка без внешних библиотек. Это отдельный контейнер для проверки; официальный контейнер использует AndroidX и собирается отдельно без изменений.
